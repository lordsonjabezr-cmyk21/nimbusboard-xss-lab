# Category 05 — Blind XSS & Internal Review Workflows

## Overview
Blind XSS is a specialized form of stored XSS where an attacker submits malicious input through an unprivileged interface (such as a public contact form, support ticket, or feedback submission), and the payload executes later inside an internal, privileged back-office application (such as an administrative moderation queue, CRM, or email digest previewer).

In NimbusBoard, Category 5 explores:
1. **Support Ticket Feedback Queue with Safe OOB Callback** (`XSS-BLIND-01`)
2. **Internal Notification Email Preview Sandbox** (`XSS-BLIND-02`)

---

## Exercise 1: XSS-BLIND-01 — Support Queue & Safe OOB Verification

### Vulnerability Context
- **Ingress Route**: `POST /api/support` (or `/support` form)
- **Review Route**: `GET /api/admin/feedback` (rendered in Admin Console)
- **Local Listener**: `http://127.0.0.1:5000/`

### Trust Boundary Crossing
- **Submitter**: Mira (`mira` — Standard User)
- **Reviewer**: Ari (`ari` — Administrator)

### Safe Verification Mechanism
NimbusBoard uses a local-only out-of-band listener that **never** collects credentials, session cookies, or browser secrets. Submitting feedback triggers an internal callback:
```javascript
// src/routes/support.js
await fetch(config.oobUrl, {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({ event: "feedback-submitted", id: item.id })
});
```

### Expected Behavior
- **Vulnerable Mode**: When the administrator opens the Support Queue, unescaped ticket content renders directly inside the admin view with `dangerouslySetInnerHTML`.
- **Fixed Mode**: The administrator console contextually encodes all ticket messages, rendering literal text without HTML execution.

## Exercise 2: XSS-BLIND-02 — Internal Email Preview Workflow

### Vulnerability Context
- **Target Route**: `GET /api/email-preview/:id`
- **Route Handler**: [src/routes/emailPreview.js](file:///c:/nimbusboard-xss-lab/src/routes/emailPreview.js)
- **Concept**: Internal teams often preview automated email digests generated by user submissions.

### Vulnerable Code Pattern
```javascript
// src/routes/emailPreview.js
if (isVulnerable()) {
  res.type("html").send(`
    <div class="email-preview">
      <h3>${email.subject}</h3>
      <div class="email-body">${email.body_html}</div>
    </div>
  `);
} else {
  res.type("html").send(`
    <div class="email-preview">
      <h3>${esc(email.subject)}</h3>
      <iframe sandbox srcdoc="${esc(email.body_html)}" style="width:100%;border:none;"></iframe>
    </div>
  `);
}
```

### Expected Behavior
- **Vulnerable Mode**: Raw email HTML renders in the parent window, sharing the same session origin.
- **Fixed Mode**: Email previews are isolated inside a sandboxed `<iframe>` (`sandbox` attribute with no script permissions), neutralizing script execution.
